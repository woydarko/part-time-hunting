# 19 → 20

## 1. Damage takes a `DamageEvent`

`CharacterStatsNode.takeDamage(amount, hitInfo?)` is now `takeDamage(event)`, from the new damage protocol (`IDamageable`, `applyDamage`, `applyAreaDamage`). `DamageHitInfo` is removed: `onDeath` and `handleDeath` receive the `DamageEvent`, which also names the `instigator` and `causer`. The engine's projectile, hitscan weapon and melee action now find any `IDamageable` on the hit, not only a `CharacterStatsNode`.

```ts nocheck
// Before (19)
stats.takeDamage(20, { hitLocation, hitNormal });
public override takeDamage(amount: number, hit?: ENGINE.DamageHitInfo): number { /* ... */ return super.takeDamage(amount, hit); }
protected override handleDeath(): void {} // keep the pawn

// After (20)
stats.takeDamage({ amount: 20, hitLocation, hitNormal, instigator: attackerRoot });
public override takeDamage(event: ENGINE.DamageEvent): number { /* ... */ return super.takeDamage(event); }
ENGINE.CharacterStatsNode.create({ deathPolicy: ENGINE.DeathPolicy.Keep }); // keep the pawn
```

`InstantHitWeaponNode.applyDamage(target, damage, hit)` is now `applyDamage(hit, event)` and returns the damage dealt; `HitInfo.damageDealt` is that amount, 0 when the target is not damageable. Team checks in `Projectile.onHit` or `applyDamage` overrides move to the receiver's `takeDamage`, which reads `event.instigator`.

## 2. Character knockback uses `launch`; speed effects stack by key

`CharacterMovementNode.launch(velocity, { overrideHorizontal, overrideVertical, steerLockSeconds })` sets or adds a world velocity. A steering lock keeps held input from cancelling the push. Replace knockback code that projected a world push into `setVelocities` and set the four lambdas to 0 for a while: it also switched off friction, and a second hit restored the lambdas early. Jump pads that called `setVelocities(0, 0, speed)` stopped a running player; launch with `overrideHorizontal: false` instead.

```ts nocheck
// Before (19)
mn.setVelocities(push.dot(fwd), push.dot(right), 6); // plus a lambda mute and a timer
mn.speedModifier = sprinting ? 1.6 : 1;

// After (20)
mn.launch(push.setY(6), { steerLockSeconds: 0.2 });
if (sprinting) mn.speedMultipliers.set('sprint', 1.6); else mn.speedMultipliers.delete('sprint');
```

`speedModifier` and `jumpStrengthModifier` stay as the saved base values; `speedMultipliers` and `jumpStrengthMultipliers` stack on top of them. Code that set `speedModifier` from several effects should give each effect a key. The `clientCorrectMovement` RPC has nine more trailing arguments (`launchVelocityX`, `launchVelocityZ`, `steerLockRemaining`, `isGrounded`, `airTime`, `jumpBufferRemaining`, `jumpBufferStrength`, `jumpBufferReleased`, `jumpCuttable`); an override must take them, and `MovementStateSnapshot` carries the same fields as optional ones.

## 3. Camera shake is built in

The engine runs camera shakes on each `PlayerController` (`playCameraShake`, `playCameraShakeAt`, `NoiseShake`). Delete a hand-written `CameraShakeNode` that wrote the camera's local pose: it fought `OrbitCameraNode` and custom rigs, froze during hitstop, and left a camera offset after a cut. Give each kind of shake a `NoiseShake` subclass with `@ENGINE.GameClass()`; `trauma` is now `intensity`.

```ts nocheck
// Before (19)
world.add(CameraShakeNode.create());
shakeNode.addTrauma(0.3);

// After (20)
@ENGINE.GameClass()
export class HitShake extends ENGINE.NoiseShake {}
ENGINE.PlayerController.findFrom(this)?.playCameraShake(HitShake, 0.3);
```

## 4. VFX presets are classes

The built-in presets are engine classes (`ENGINE.FireVFX`, `ENGINE.ExplosionVFX`, `ENGINE.HitSparksSmallVFX`, …), and a game can write its own (`extends ENGINE.VFXPreset`). Code that set `VFXNode.preset` to an id passes the class; saved scenes keep loading, since the old ids map to the classes. `world.globalParticleManager.spawnPreset(PresetClass, at, options)` plays one at a point. The manager now caps live one-shot effects itself (`maxLiveEffects`, 32), so delete a hand-written `getAttachedVFX().length` check. `VFXPresets`, `VFX_PRESET_IDS` and `VFXPresetId` are gone. Reading `VFXNode.preset` returns the preset class's registered name (`'ENGINE.FireVFX'`) or `'none'`, not the old id, so a check such as `node.preset === 'fire'` no longer matches: compare with `'ENGINE.FireVFX'`.

```ts nocheck
// Before (19)
ENGINE.VFXNode.create({ preset: 'fire' });
if (gpm.getAttachedVFX().length < 32) void gpm.spawnVFX('hitSparks', HIT_PARTICLES, HIT_EMITTER, { position: at });

// After (20)
ENGINE.VFXNode.create({ preset: ENGINE.FireVFX });
void gpm.spawnPreset(ENGINE.HitSparksSmallVFX, at);
```

## 5. Sound pitch and limits are built in

One-shots take `playbackRate`, `pitchVariation` (semitones), `maxVoices` and `minInterval` (seconds), and the manager drops one-shots past `maxSounds` (32). `SoundResource` has `playbackRate`, `pitchVariation` and `minInterval`. Delete a hand-written per-clip cooldown map, a `getPlayingSoundCount()` cap, and random `setPlaybackRate` calls before `SoundNode.play`.

```ts nocheck
// Before (19)
if (now - (lastPlayed.get(clip) ?? 0) < 60 || audio.getPlayingSoundCount() >= 24) return;
steps.getAudio(key)?.setPlaybackRate(0.95 + Math.random() * 0.1);

// After (20)
void audio.playSoundAtPosition(clip, at, { minInterval: 0.06, maxVoices: 4, pitchVariation: 0.7 });
stepResource.pitchVariation = 0.8;
```

## 6. Locked doors: `onOpenRefused`, keys and `target`

A refused open on a locked `DoorNode` now raises `onOpenRefused`; `onDoorLocked` fires only when the door gets locked. Move a rattle sound or "Locked" toast to `onOpenRefused`. Delete a hand-written key check on `onInteractionAttempt`: set `requiredKey` and implement `ENGINE.IKeyHolder` (`hasKey`) on the pawn or controller. A door whose panel is not the first `ModelMeshNode` sets `target`. `open({ instant: true })`, `close({ instant: true })`, `reset()` and `startOpen` replace hand-set transforms after a load. Sliding doors on a turned actor now slide along the actor's own `slideDirection`, not a twice-turned one.

```ts nocheck
// Before (19)
door.onDoorLocked.add(() => playRattle());
door.onInteractionAttempt.add(() => { if (door.isLocked() && player.hasRedKey) { door.unlock(); door.open(); } });

// After (20)
door.onOpenRefused.add(() => playRattle());
ENGINE.DoorNode.create({ startLocked: true, requiredKey: 'red' }); // the pawn or controller implements IKeyHolder
```

## 7. Pickups respawn in place

`PickupNode` gets `destroyOnCollect`, `respawnTime`, `reset()`, `isAvailable` and `onRespawned`. Delete a hand-written respawn: an `onPickupInternal` override that skips `super`, hides the root and turns physics off and on with `overridePhysicsOptions`. Turning physics on for the whole root also gave a collider to every child that had none. A `WeaponPickupNode` or similar subclass with its own `respawnTime` field drops it (the base has one now). `PickupSpawnerNode` now refills when its pickup leaves play for any reason, not only on `onPickup`.

```ts nocheck
// Before (19)
protected override onPickupInternal(collector: ENGINE.SceneNode): void {
  giveAmmo(collector);
  root.visible = false; root.overridePhysicsOptions({ enabled: false }, true);
  world.timerSystem.setTimeout(() => { root.visible = true; root.overridePhysicsOptions({ enabled: true }, true); }, 15);
}

// After (20)
ENGINE.PickupNode.create({ destroyOnCollect: false, respawnTime: 15 }); // the override calls super.onPickupInternal(collector)
```

## 8. Physics materials and damping options

Bodies get friction and bounciness from a `PhysicsMaterial` (`physicsOptions.physicsMaterial`, or `node.physicsMaterial` during play), and damping from `physicsOptions.linearDamping` and `angularDamping`. Delete a hand-written bounce that wrote a reflected velocity on every collision event, and damping used to fake friction. Damping set only with `setScalarParam` was lost whenever the body was rebuilt; move it to the options. A change to `physicsMaterial`, damping or `gravityScale` with `overridePhysicsOptions` now applies without a rebuild. The engine damping comment said 0 to 1; damping is 0 or more. `resourceManager.onResourceInvalidated` (a path, or null for all) fires when a resource file leaves the cache, and `invalidateResourceCache` now also drops that file's cached JSON, so the next load reads the file again; code that reloaded a resource after an invalidation and still got the old contents now gets the new ones.

```ts nocheck
// Before (19)
ball.onCollideWith.add((self, other, event) => reflectVelocity(self, event, 0.8));

// After (20)
ball.physicsMaterial = ENGINE.PhysicsMaterial.create({ restitution: 0.8, restitutionCombine: ENGINE.PhysicsCombineRule.Max });
```

## 9. Pawn change events; a destroyed pawn is released

`controller.onPawnChanged(pawn, previous)` and `world.onPlayerPawnChanged(controller, pawn, previous)` fire when a controller's pawn changes: possess, a respawn, unpossess, and on a client when the replicated pawn arrives. Replace code that polled `getFirstPlayerPawn()` or `getPawn()` every tick to notice a respawn, and listeners re-added to each new pawn by hand. A possessed pawn that is destroyed is now released by its controller, so `getPawn()` returns null instead of the destroyed pawn; code that read the dead pawn after its death must keep its own reference. When the level ends (play stops, or `openLevel`) pawns are not released and no change fires, so a respawn listener does not run during teardown. Likewise `GameMode.getPlayerPawnForClient` forgets a destroyed pawn, so `onPlayerDisconnected` receives null for a player who left while dead.

```ts nocheck
// Before (19)
tick() { const pawn = world.getFirstPlayerPawn(); if (pawn !== this.lastPawn) { this.lastPawn = pawn; this.bind(pawn); } }

// After (20)
world.onPlayerPawnChanged.add((_controller, pawn) => this.bind(pawn));
```

## 10. Waiting to compile ahead: `whenReadyToCompile`

`world.whenReadyToCompile()` resolves true once `precompileForRender` builds for the contexts the next frames draw with; it looks just after each drawn frame and asks the editor viewport for frames meanwhile. It resolves false after `timeoutMs` (default 2000) or when the world is destroyed, and never rejects. `precompileForRender(object, { wait: true })` waits that way first and compiles again when the post-process chain was rebuilt meanwhile, up to three compiles in all; when the wait times out it compiles once anyway. Replace loops that polled `canPrecompileForRender()` every frame or counted frames before compiling. The anime toon tier change now waits for the renderer instead of skipping its compile.

```ts nocheck
// Before (19)
while (!world.canPrecompileForRender()) await nextFrame();
if (!(await world.precompileForRender(group))) await world.precompileForRender(group);

// After (20)
await world.precompileForRender(group, { wait: true });
```

## 11. `getGrounded()` became `canGroundJump`; `isGrounded` and `coyoteTime` are public

`CharacterMovementNode.getGrounded()` is removed. It returned true for 100 ms after walking off a ledge (coyote time), so code that used it for landing effects, footsteps or a falling animation was late by that much. Use the getter `isGrounded` for standing on the ground now (false while moving up from a jump or a launch, even within a few centimetres of the floor, so a weak jump can no longer jump again on the way up), and `canGroundJump` (the old result) only to ask whether a jump counts as a ground jump. Coyote time is the public property `coyoteTime` in seconds (default 0.1; option `coyoteTime`), replacing the protected `coyoteTimeMs` in milliseconds. The replicated field is now `grounded`, and its hook `onRepGrounded` replaces `onRepIsGrounded`. `CharacterPawn.getPlanarLocomotion().grounded` now reads `isGrounded`, so the falling animation starts when the feet leave the ground.

| 19 | 20 |
|---|---|
| `movement.getGrounded()` | `movement.isGrounded` (touching now) or `movement.canGroundJump` (with coyote time) |
| `coyoteTimeMs = 100` in a subclass | `movement.coyoteTime = 0.1` |
| `override onRepIsGrounded()` | `override onRepGrounded()` |
| `this.lastGroundedTime` (protected, `performance.now()` milliseconds) | `this.airTime` (protected, seconds since leaving the ground; `Infinity` after a jump or launch) |

## 12. Trace profiles; `CanSeeTargetCondition` traces physics

Two built-in profiles are for queries. `WorldOnlyTrace` asks about the level: bodies on the world static, world dynamic and destructible channels block it, while bodies with the `Pawn`, `Character`, `Vehicle` or `Ragdoll` profile never do (a vehicle or prop left on `BlockAll` counts as level geometry). Use it for floor probes, placement, free-space checks and blast cover. `VisibilityTrace` is for line of sight: each body decides by its response to the Visibility channel, so `Pawn` and `Character` bodies let it through and a custom profile that ignores Visibility makes glass or foliage see-through. Line-of-sight code that used `SpringArmCamera` should move to `VisibilityTrace`, so a camera tweak no longer changes what NPCs see.

`CanSeeTargetCondition` now casts a physics ray with `VisibilityTrace` instead of raycasting every render mesh, so NPC sight changes: other characters and meshes with no collider no longer block it, and invisible walls now do. In a world without physics it checks distance only. If an NPC now sees through something that should hide the player, give that object a collider.

## 13. Instanced nodes keep early edits and update bounds once per frame

`InstancedMeshNode` and `InstancedModelMeshNode` build their buffers when they start play, or when the model finishes loading. Edits made before that used to be lost: `addInstance` returned -1 and `setInstanceTransforms` emptied the saved `instances`. They are now kept and drawn once the buffers exist, and `addInstance` returns the real id, so `await waitForLoad()` is no longer needed before editing instances. Mesh bounds used to be recomputed over every instance after each edit, which made adding instances one at a time slow; they are now recomputed at most once per frame, and before a raycast against the node. Code that reads `getInstancedMesh().boundingSphere` right after an edit calls `node.flushBounds()` first. `isWorldSpace` is removed: `instances` are always relative to the node, so moving the node moves them, and world-space transforms are converted at the call: pass `true` as the last argument of `addInstance`, `addInstances`, `setInstanceTransform(s)`, `updateInstance(s)` and `getInstanceTransform` / `getInstancesTransforms`. A scene saved with `isWorldSpace: true` loads its instances where they were drawn, converted to node space once, and the next save drops the flag. Before, a world-space node converted its instances to node space when the buffers were built, and a rebuild (an editor property change, `pushInstanceData`) or a save moved them when the node was not at the origin. Code that set `isWorldSpace: true` drops it and passes `true` on each edit, or keeps the node at the origin.

## 14. Changed defaults and behaviour: jump buffer, shotgun, first shot, weapon aim, restart, collider scale, class names

These need no code change unless a game relied on the old behaviour.

- `CharacterMovementNode.jumpBufferTime` defaults to 0.1 s: a jump pressed up to 0.1 s before landing jumps on landing. In 19 that press was lost. Set `jumpBufferTime` to 0 to keep that, and delete a hand-written jump buffer.
- `ShotgunNode` fires 8 gold pellets in a 0.08 rad cone for one shell, 5 damage each (40 when all hit). In 19 it fired one 25-damage slug. To fire one slug, pass `pelletCount: 1`, `spread: 0` and `projectileOptions` with `damageDealt: 25`; `projectileOptions` replaces the whole default, so give the projectile's size and material too.
- A weapon's first press fires at once, even on the first frame of play. In 19 it fired only after one `fireInterval` had passed since play started.
- A weapon with no camera and no target fires along its own forward (-Z). In 19 it fired along +Z, backwards, so a turret turned 180 degrees to make up for it turns back.
- `PlayerController.restartPlayer()` places the pawn with `teleport`, so it arrives standing still: speed, used air jumps and coyote time are cleared. In 19 a player who fell to their death was still falling after the respawn. Delete code that cleared the speed after a restart. To place a pawn and keep its speed, call `pawn.teleport(transform, { keepVelocity: true })`.
- A body's colliders follow its world scale: scaling the node, or any parent, during play resizes them. In 19 they kept the size they were built with. A game that scaled a parent for looks only and relied on the old collider size scales the visual child instead.
- Two game classes registered with the same name now throw in development too, with a message that says to rename one. In 19 development silently replaced the first with the second, while a published build failed to start. Rename one of the two classes.

## 15. `gameTime` is a property

`world.gameTime` and `blackboard.gameTime` replace `getGameTime()`, like `realTime`, `timeScale` and `paused`. The methods still work and are deprecated.

```ts nocheck
// Before (19)
const now = world.getGameTime();

// After (20)
const now = world.gameTime;
```
